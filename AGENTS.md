# Работа с репозиторием

- Перед началом изменений проверь `git status`, выполни `git fetch origin` и обнови рабочую ветку до актуального удалённого состояния. На чистой `main` используй `git pull --ff-only`.
- Перед push снова выполни fetch. Если команда успела обновить ветку, интегрируй изменения без force push и повтори затронутые проверки.
- После завершённого изменения выполни проверки, сделай commit и push. Не оставляй готовые изменения только локально.
- Основа — выбранная лучшая модель в `train.py` и подтверждённый сабмит в `results/submission.csv`. Меняй её после проверки; сохраняй воспроизводимость выбранного результата.
- Держи один рабочий pipeline. Не добавляй в Git окружения, веса, кэши, поисковые дампы, дубли исходных данных и промежуточные модели. История экспериментов доступна через Git.
- Сохраняй обязательные материалы ТЗ: обучение и валидацию, сборщик с URL источников и проверкой данных, собранную внешнюю базу с SMILES/IC50/CC50/SI/DOI, фактический обучающий набор и воспроизводимый CSV.
- Репозиторий приватный. Не меняй его видимость и не публикуй данные соревнования отдельно.

- Учитывай лимит Kaggle: сравнивай кандидатов локально на одинаковых молекулярных и scaffold-разбиениях. Отправляй только существенное устойчивое улучшение; небольшие и неоднозначные изменения сохраняй как локальные эксперименты. У отправок добавляй содержательное описание.

- Последнее указание пользователя: отправки в Kaggle остановлены. Пушь готовые изменения и кандидатов в Git; в Kaggle не загружай и не отправляй без нового явного указания пользователя. Это отменяет прежнее разрешение автоматически отправлять сильные кандидаты.
